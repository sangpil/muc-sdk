# muc-sdk

The thin contract between **MUC Life Builder** (the engine) and the projects it opens — your app, its core packages, its preview host and its project tool.
Both sides depend on this one Swift package; it depends on nothing.

엔진(MUC Life Builder)과 그 엔진이 여는 프로젝트(앱 · 코어 · 미리보기 호스트 · 프로젝트 도구)가 함께 무는 **얇은 계약** 한 패키지다. 이 패키지는 아무것도 물지 않는다(잎).

```
engine (builder) ──▶ muc-sdk ◀── project (app · core · preview host · project tool)
```

## Install · 설치

Pin an exact version — the engine and your project must resolve the same one.
판을 못 박는다(`exact:`) — 한 그래프에 두 판이 들면 SwiftPM 이 해석에서 거부한다.

```swift
// Package.swift
dependencies: [
    .package(url: "https://github.com/sangpil/muc-sdk.git", exact: "5.3.0"),
],
targets: [
    .target(name: "MyScreens", dependencies: [
        .product(name: "ProjectFormat", package: "muc-sdk"),
        .product(name: "ScreenMarks", package: "muc-sdk"),
    ]),
]
```

Platforms: macOS 14 · iOS 17 · tvOS 26 (runtime products are macOS only — empty modules on iOS and tvOS).
플랫폼: macOS 14 · iOS 17 · tvOS 26(런타임 제품은 macOS 전용 — iOS · tvOS 에서는 빈 모듈).
Toolchain: Swift 6.1 or newer — this package's manifest is `swift-tools-version: 6.1` (package traits).
툴체인: Swift 6.1 이상 — 이 패키지의 매니페스트가 트레이트를 쓰는 `swift-tools-version: 6.1` 이다.

### Element marks in your tool build · 도구 빌드에서 요소 표식 켜기

`.snapID` is an empty modifier unless the `ActiveMarks` trait is on (and only on macOS — iOS is always off).
Pass it from a trait of your own, so your app build never carries it and your tool build does. Using traits needs `swift-tools-version: 6.1` in your manifest too.
A mark never changes layout — with the trait on or off, the marked view keeps the same frame and its alignment guides still reach the parent (overlays included).
`.snapID` 는 트레이트 `ActiveMarks` 가 켜졌을 때만(그리고 macOS 에서만 — iOS 는 늘 꺼짐) 앵커 · 탭을 건다. 제 패키지의 트레이트로 넘긴다 — 앱 빌드엔 없고 도구 빌드에만 선다.
표식은 레이아웃을 바꾸지 않는다 — 트레이트가 켜지든 꺼지든 표식 단 뷰의 프레임이 같고, 정렬 안내선이 바깥(overlay 포함)에 그대로 닿는다.

```swift
// swift-tools-version: 6.1
// Package.swift
let package = Package(
    name: "MyApp",
    traits: [
        .trait(name: "ToolBuild", description: "Element marks for the engine's tools"),   // off by default · 기본 꺼짐
    ],
    dependencies: [
        .package(url: "https://github.com/sangpil/muc-sdk.git", exact: "5.3.0",
                 traits: [.trait(name: "ActiveMarks", condition: .when(traits: ["ToolBuild"]))]),
    ],
    targets: [
        .target(name: "MyScreens", dependencies: [.product(name: "ScreenMarks", package: "muc-sdk")]),
    ]
)
```

```sh
swift build --traits ToolBuild     # tool build — marks on (macOS) · 도구 빌드
swift build                        # app build — marks are empty modifiers · 앱 빌드
```

## Products · 제품

| Product | Branch · 갈래 | What · 무엇 |
|---|---|---|
| `ProjectFormat` | contract · 계약 | Project document formats — one version per format (version constants · version reader), `.isodata` model files, change-log rules for shared data, design files, screen components, IA document, JSON value · 프로젝트 문서의 형식 · 공유 데이터의 변경 기록 규약 |
| `ScreenMarks` | contract | Element marks `.snapID` — active only with the `ActiveMarks` trait on macOS · 화면 요소 표식 |
| `DesignTokens` | contract | Design token shapes — colors, scales, providers, source-of-truth readers · 디자인 토큰의 꼴 |
| `LaunchTrace` | contract | Window-open timing hook `OpenTrace` · 창 열기 실측 훅 |
| `PreviewProtocol` | contract | Engine ⟂ preview host messages, framing, protocol version, style schema · 엔진 ⟂ 미리보기 호스트의 말 |
| `SpokenTime` | contract | Reads the time a Korean sentence speaks of — `SpokenReading.read` (a span of days or a question) · `day` (one day) · `end` (the end day) · `hasSpanSignal` · 말한 때 읽기 |
| `PreviewWire` | runtime (macOS) | Transport — Unix socket connection, shared memory · 전송 |
| `PreviewHostKit` | runtime (macOS) | Preview host runtime — `PreviewHost.main(…)`, screen/session protocols, renderer, drawn text · background readback · 호스트 런타임 |
| `TestScratch` | test · 시험 | Scratch folders and defaults for tests only · 시험의 임시 자리 한 벌 |

Your app links contract products only. Your preview host (an executable in your own package that the engine builds and launches) links `PreviewHostKit`.
앱은 계약 제품만 문다 · 미리보기 호스트(프로젝트가 제 패키지에 두는 실행물 — 엔진이 빌드해 띄운다)가 런타임 제품을 문다.

### Spoken time words · 말한 때의 낱말

`SpokenTime` keeps every word and pattern it reads in one resource file, `Sources/SpokenTime/Resources/words.json` — the source code holds none (the gate checks that its code outside comments carries no non-ASCII letter and no `\u{` escape). The file is one JSON object: `patterns` (name → regular expression; `{name}` inside a pattern is replaced by the pattern of that name), the rule tables `grades` · `anchored` (event words → context key) · `modifiers` (what follows an event word) · `stages` · `stageRest` · `school`, and the word tables (`weekday` · `seasons` · `yearOffset` · `monthOffset` · `dayOffset` · `nativeDays` · …). The shape belongs to the module, not to the public surface. SwiftPM ships it in the bundle `muc-sdk_SpokenTime`; a consumer that assembles its own app or tool must carry that bundle next to the binary — without it the first read stops.
`SpokenTime` 은 읽는 낱말 · 꼴을 자원 파일 하나 `Sources/SpokenTime/Resources/words.json` 에만 둔다 — 소스에는 없다(게이트가 소스의 주석 밖 코드에 ASCII 밖 글자 · `\u{` 이스케이프 0 을 잰다). 파일은 JSON 객체 하나다: `patterns`(이름 → 정규식 · 꼴 안의 `{이름}` 은 그 이름의 꼴로 바꿔 끼운다) · 규칙 표 `grades` · `anchored`(사건 낱말 → 맥락 키) · `modifiers`(사건 낱말 뒤의 수식) · `stages` · `stageRest` · `school` · 낱말 표(`weekday` · `seasons` · `yearOffset` · `monthOffset` · `dayOffset` · `nativeDays` · …). 꼴은 모듈 안의 약속이다(공개 표면 밖). SwiftPM 이 번들 `muc-sdk_SpokenTime` 으로 싣는다 — 앱 · 도구를 제 손으로 조립하는 쪽은 그 번들을 실행물 곁에 함께 싣는다(없으면 첫 읽기에서 멈춘다).

## Versioning · 판

- **SDK version** = `ProjectFormat.SDKVersion.current` = the repository tag. Tags are never moved; a fix bumps the version.
  SDK 판 = 저장소의 판 꼬리표 · 한 번 찍은 꼬리표는 다시 찍지 않는다.
- **Protocol version** (`PreviewProtocolVersion.current`) is counted separately; the engine accepts a host of its own protocol version only, so a version that raises it moves the builder and the project together. One preview host process serves many connections — one connection is one session.
  프로토콜 판은 따로 센다 · 엔진은 같은 프로토콜 판의 호스트만 받는다(판을 올리는 SDK 판은 빌더와 프로젝트가 함께 옮긴다) · 호스트 하나가 연결을 여럿 받는다(연결 = 세션).
- **Pinning SDK 1.1 moves your preview host to protocol version 4** — the builder (engine) must be on SDK 1.1 or newer too; an older builder refuses the host with "update the builder".
  SDK 1.1 로 핀을 올린 프로젝트의 호스트는 프로토콜 판 4 — 빌더(엔진)도 1.1 이상이어야 한다(옛 빌더는 「빌더를 업데이트하세요」로 거절).
- **SDK 1.2 adds an optional field to the IA document** (`ScreenNode.entry` — which screen · what kind of control · which element). The protocol stays at version 4 and the IA format at version 1; a 1.1 reader keeps the field as an unknown key.
  SDK 1.2 는 IA 문서에 선택 칸 하나(`ScreenNode.entry` — 어느 화면 · 무엇을 · 요소)를 더한다 — 프로토콜 판 4 · IA 형식 판 1 그대로 · 1.1 읽개는 모르는 칸으로 보존한다.
- **SDK 1.3 adds image slots to the style schema** (`StyleSlot` · `StyleSchema.slots` — the host declares where an image sits; the value is one string in the style dictionary: empty = the original image, or `isomodel:<name>`). The shelf is a folder the project chooses; the name is a file name in that folder without its extension, and resolving it is up to the host and the app — the SDK promises only the value's shape. The host and the app draw the model in that place. This moves the preview host to protocol version 5 even if it declares no slots — the builder must be on SDK 1.3 or newer too.
  SDK 1.3 은 Style 서술에 이미지 자리를 더한다(`StyleSlot` · `StyleSchema.slots` — 호스트가 이미지 자리를 선언 · 값은 Style 값 사전의 글자 하나: 빈 글 = 원래 이미지 ⟂ `isomodel:<이름>`). 서가는 프로젝트가 정하는 폴더 — 이름은 그 폴더의 파일 이름(확장자 없이)이고 풀이는 호스트 · 앱 몫(SDK 는 값의 꼴만 약속한다). 그 자리에 모델을 그리는 것은 호스트와 앱 — 자리를 선언하지 않아도 호스트는 프로토콜 판 5 · 빌더도 1.3 이상이어야 한다.
- **SDK 1.4 lets a preview session wait before a frame** (`PreviewSession.prepare(_ context: RenderContext)` — async, default returns at once; the context is the frame's size · theme · offscreen flag, so a session warms the picture for that appearance — key its cache by name *and* appearance). The host awaits it before every picture it draws (`render` · `patch` · tokens changed · `shot` · its own window), so an offscreen frame shows a slot's model from the first frame instead of an empty slot while the model is still being drawn. Messages that arrive meanwhile wait their turn (patches merge). A preparation that outlives the host's limit (20 s, inside the engine's wait) or a session that closes meanwhile is cancelled — cooperative cancellation; a frame cut at the limit is final (no redraw signal follows), and a source that ignores cancellation may be asked again while still running, so share in-flight work. Nothing on the wire changes — the protocol stays at version 5, so a 1.4 host works with a 1.3 builder and a 1.3 host works with a 1.4 builder (it draws as before). A session that implements nothing draws exactly what it drew on 1.3.
  SDK 1.4 는 미리보기 세션이 장을 그리기 전에 기다릴 손을 더한다(`PreviewSession.prepare(_ context: RenderContext)` — 비동기 · 기본은 곧장 · 문맥 = 그 장의 크기 · 테마 · 창 없는 렌더인가 — 그 외양의 그림을 데운다 · 캐시는 이름과 외양으로). 호스트가 그리기 전마다(`render` · `patch` · 토큰 바뀜 · `shot` · 자기 창) 기다려서, 창 없는 장도 모델을 그리는 중의 빈 자리가 아니라 첫 장부터 자리의 모델을 그린다. 그 사이 온 메시지는 차례대로 뒤에 선다(patch 는 합쳐진다). 호스트의 시한(20 초 — 엔진이 기다리는 시한 안)을 넘긴 준비 · 그 사이 닫힌 세션의 준비는 취소된다(협력 취소 — 시한에 잘린 장은 끝난 장이고 다시 그리라는 신호가 없다 · 취소를 무시한 원천은 다음 준비와 겹쳐 불릴 수 있어 진행 중인 일을 나눠 기다린다). 와이어는 그대로다 — 프로토콜 판 5 라 1.4 호스트 ⟂ 1.3 빌더 · 1.3 호스트 ⟂ 1.4 빌더가 다 선다(1.3 호스트는 예전처럼 그린다). 아무것도 구현하지 않은 세션은 1.3 과 같은 장을 낸다.
- **SDK 1.5 reads back the text and backgrounds a screen drew** — a render may ask for them (`RenderRequest.drawn`); the host draws that frame once more as a vector page and reads it (public CoreGraphics PDF scanning · PDFKit), and the frame header carries every drawn text line (`DrawnText` — string · box · font name · size · weight · color · the innermost marked element around it) and, per marked element, the fill painted exactly on its bounds (`DrawnStyle` — color · corner radius). Screen code adds nothing — no new modifier; elements already marked with `.snapID` get their text and background. Protocol version 6 (a 1.5 host needs a 1.5 builder; a 1.5 builder still talks to 1.3 · 1.4 hosts and reads "no text" from them).
  SDK 1.5 는 화면이 그린 글줄 · 바탕을 읽어 싣는다 — render 가 청하면(`RenderRequest.drawn`) 호스트가 그 장을 벡터 한 쪽으로 한 번 더 그려 읽고(공개 CoreGraphics PDF 걷기 · PDFKit), 프레임 머리에 그린 글줄 전부(`DrawnText` — 글 · 상자 · 글꼴 이름 · 크기 · 굵기 · 색 · 그 줄을 품은 가장 안쪽 표식 요소)와 표식 요소마다 그 경계에 칠한 바탕(`DrawnStyle` — 색 · 모서리 반경)을 싣는다. 화면 코드는 아무것도 달지 않는다 — 새 모디파이어 없음 · `.snapID` 를 이미 단 요소의 글자 · 바탕이 잡힌다. 프로토콜 판 6(1.5 호스트는 1.5 빌더가 받는다 · 1.5 빌더는 1.3 · 1.4 호스트와도 말하고 그 호스트의 머리는 글줄 없음).
  **1.5.1** keeps the spaces inside a drawn line — one space per drawn space glyph (a non-breaking space or a tab comes as one U+0020), one space where a font-fallback run left only a gap (between Hangul words in the system font), leading and trailing spaces trimmed — and reading a drawn page leaves no CoreGraphics PDF error line on stderr. Protocol stays at version 6.
  **1.5.1** 은 그린 글줄 안의 공백을 싣는다 — 그린 공백 글자마다 공백 하나(줄바꿈 없는 공백 · 탭은 U+0020 하나) · 글꼴 대체 런이 벌림만 남긴 자리(시스템 글꼴의 한글 낱말 사이)에 공백 하나 · 앞뒤 공백은 다듬는다 — 호스트가 stderr 에 CoreGraphics PDF 오류 줄을 찍지 않는다. 프로토콜 판은 6 그대로.
- **SDK 1.6 lets a style element declare the system effects it uses** (`StyleElement.effects` — an open vocabulary `StyleEffect`: `glass` · `material` · `blur` · `shadow` · `motion`, unknown words kept as they are). It is a statement of fact — "this element is drawn with glass" — so the engine marks exactly that element instead of guessing from field names; whether a renderer can draw the effect is the engine's call. One line in the schema: `StyleElement(id: "card", label: "Card", snapPrefix: "garden.card", effects: [.glass])`; the old initializer stays. Protocol version 7 even if no element declares an effect (a 1.6 host needs a 1.6 builder; a 1.6 builder still talks to 1.5 hosts and reads "nothing declared" from them).
  SDK 1.6 은 Style 서술의 절이 제가 쓰는 시스템 효과를 선언하게 한다(`StyleElement.effects` — 열린 낱말 `StyleEffect`: `glass` · `material` · `blur` · `shadow` · `motion` · 모르는 낱말도 그대로 든다). 사실의 선언이다 — 「이 요소는 유리로 그려진다」 — 엔진은 칸 이름으로 짐작하지 않고 그 요소에만 표지를 단다 · 어느 렌더가 그 효과를 그리지 못하는가는 엔진의 판단이다. 서술에 한 줄: `StyleElement(id: "card", label: "카드", snapPrefix: "garden.card", effects: [.glass])` · 옛 이니셜라이저는 그대로. 효과를 하나도 선언하지 않아도 프로토콜 판 7(1.6 호스트는 1.6 빌더가 받는다 · 1.6 빌더는 1.5 호스트와도 말하고 그 호스트의 서술은 선언 없음).
  **1.6.1** reads the drawn text and backgrounds of a frame with a material in it: the vector pass alone draws materials in their inactive appearance (public `materialActiveAppearance`, macOS 15+ — the PNG stays as it is), so the page no longer turns into one raster image with no lines; a material element's background is that solid approximation (an element that declares `effects: [.material]` tells the engine so), and fills stacked on one element's bounds give their composited visible color. Glass has no public switch: once the host process has opened a window (its own window), glass is really drawn and the vector pass of that frame is one raster image again (no lines, no backgrounds); with no window, glass and the content inside it are not drawn at all, not in the PNG either (measured on macOS 27, outside the tests — a window once opened in a process cannot be undone) — so draw glass as an approximation when `RenderContext.offscreen` is true. Protocol stays at version 7.
  **1.6.1** 은 머티리얼이 있는 장의 그린 글줄 · 바탕을 읽는다 — 벡터 그림에서만 머티리얼을 비활성 외양으로 그려(공개 `materialActiveAppearance` · macOS 15 이상 · PNG 는 그대로) 그 장이 글줄 없는 래스터 한 장이 되지 않는다 · 머티리얼 요소의 바탕은 그 단색 근사다(`effects: [.material]` 을 선언한 요소면 엔진이 안다) · 한 요소의 경계에 겹친 칠은 합성한 보이는 색이다. 유리는 공개 손으로 끌 수 없다 — 호스트 프로세스에 창이 하나라도 섰으면(자기 창) 유리가 진짜로 그려지고 그 장의 벡터 그림이 다시 래스터 한 장(글줄 · 바탕 0) · 창이 없으면 유리와 그 안의 내용이 PNG 에도 그려지지 않는다(실측 · macOS 27 · 시험 밖 — 한 프로세스에서 선 창은 되돌릴 수 없어 창 없는 상태는 시험이 붙들지 못한다) — `RenderContext.offscreen` 이 참이면 유리를 근사로 그린다. 프로토콜 판은 7 그대로.
  **1.6.2** renames a style field in the SDK's own tests to a neutral sample name — no API, file or wire change. Protocol stays at version 7.
  **1.6.2** 는 SDK 제 시험의 Style 칸 이름 하나를 중립 견본 이름으로 바꾼다 — API · 파일 · 와이어 변화 0. 프로토콜 판은 7 그대로.
- **SDK 1.7 lets a render say "this frame is a printed page"** (`RenderRequest.page` → `RenderContext.page`, default `false`). A page is a sheet of paper, not a device screen: a screen that picks a device look from its size (display corners, safe areas) should not apply it when `context.page` is true — corner 0, safe area 0. One optional branch in your screen frame; without it the page is drawn as before. Protocol version 8 (a 1.7 host needs a 1.7 builder; a 1.7 builder takes 1.6 hosts and drops the mark for them). - **SDK 3.1 adds the change-log rules for shared data** (`ChangeLog` — pure rules; the hook that writes the lines on save, the store and sync stay in your app). Days are noon in the given zone. `SpokenReading.day(_:now:zone:direction:)` reads one day as far as the sentence says it (`exact` · `month` · `year` · `circa`, the first day of that unit), `SpokenReading.end(_:start:now:zone:direction:)` reads the end the sentence states (`…부터 …까지`, or `N박` after an exact start; a missing year or month comes from the start and rolls over when the end would fall before it) and `SpokenReading.hasSpanSignal(_:)` says whether the sentence speaks of a stretch of time. All three time readers take a `direction` (`SpokenReading.Direction` — `past`, the default, or `future`) that the caller passes from its own classification of the sentence; a modifier the sentence states always wins, and `future` changes three readings — a two-digit year or decade (`98년` · `90년대`: `past` puts it in the reference year's century and moves it back a century if that lands after the reference year, `future` takes the closest such year at or after the reference year), a month or month and day with no modifier (the closest one from today on) and a season with no modifier (the closest one not yet over). The value types inside a reading are `Codable` (the `SpokenReading` result enum itself is not — store the values it carries); the reason of a question is an open vocabulary (`SpokenReading.Ask.Reason` — unknown words kept as they are), and `SpokenReading.Day(year:month:day:precision:zone:)` builds a start day. The words live in the module's resource file (above), so it is the package's first resource bundle. Nothing else changes — no file, wire or protocol change; protocol stays at version 10. With several sentences, a repeat stays in its own sentence: another sentence's time wins (`그저께 삼촌을 만났어. 삼촌은 매일 낚시를 해` is the day before yesterday) unless the repeating sentence sets its own span (`1977년부터 매일 달렸어. 1980년까지 계속했어.` is 1977), and with no such time it repeats as before. `phrase` leaves out what was set aside. A repeat in the final clause is unchanged (`삼촌은 매일 낚시를 해` repeats). Same public names, protocol stays at version 10 — a patch version.
  **5.2.2** 는 읽기 하나를 고친다 — 되풀이 낱말(「매일 · 매주 · …마다」)이 문장을 되풀이로 바꾸는 것은 그 낱말이 사건을 말하는 마디(문장의 끝 풀이말)에 걸릴 때뿐이다. 이름씨를 꾸미는 마디 안의 되풀이는 그 이름씨를 꾸밀 뿐이라 그 마디(앞에 붙은 수 · 달 · 날 · 계절 포함 — 「4년마다」 · 「5월 3일마다」 · 「4월에 매년」)를 가르고 나머지에서 때를 읽는다(「그저께 매주 들르던 꽃집에 들렀어」 = 그저께 · 「1977년에 날마다 오르던 언덕을 깎았어」 = 1977년 · 「비 올 때마다 걷던 둑길이 사라졌어」 = 때 없음). 꾸미는 마디 = 「-던」 + 이름씨(사이 낱말 둘까지 — 사이 낱말이 임자말 · 토씨 · 이음 · 맺음 꼴이거나 때면 마디 밖: 「매일 내가 살던 집에 가」 = 되풀이) · 「-는」 + 이름씨(되풀이 낱말 바로 뒤 풀이말 줄기만 · 토씨 「는」과 꼴이 겹치니 날이 선 다른 때가 있을 때만 — 「매일 누나는 …」 = 되풀이) · 뒤가 매인 이름씨(것 · 거 · 중 · 편 · 때 · 모양 …)면 끝 풀이말의 한 꼴이다. 여러 문장이면 되풀이는 제 문장의 일 — 다른 문장의 때가 이기고(「그저께 삼촌을 만났어. 삼촌은 매일 낚시를 해」 = 그저께) 되풀이 문장이 제 구간을 세우면 그 답이며(「1977년부터 매일 달렸어. 1980년까지 계속했어.」 = 1977년) 그런 때가 없으면 전처럼 되풀이다. `phrase` 에서는 가른 토막이 빠진다. 끝 풀이말 마디의 되풀이는 그대로다(「삼촌은 매일 낚시를 해」 = 되풀이). 공개 이름 그대로 · 프로토콜 판 10 그대로 — 수 판이다.
- **SDK 5.3 asks when one clause says two times that do not overlap, and stops reading what is not a time.** `SpokenReading.Ask` gains `candidates` (the spans, in the order the sentence says them) and `direction`, and `Ask.Reason` gains `conflict`; older JSON without the new fields still reads, and an `Ask` whose new fields are empty writes the same bytes as 5.2. **Heads-up for callers — answers that change:** (1) *Two times.* Where 5.2 picked one in the order absolute > relative > birth date, 5.3 returns `.ask` with `conflict` and the spans when two times that stand side by side in one clause — joined by `그리고` or a comma, or the first set off by a comma and the second marked with `에` — do not overlap (`30년 전, 내가 30대에 우물을 팠어` · `재작년 그리고 올해 거뒀어`) — and `day` is nil there. The old order now only names a narrowed span. Two times joined by a connective (`-아서 · -고 · -고서 · -고 나서 · -다가 · -는데 · -지만 · 에 이어`) or with a verb between them keep the answer of 5.2 (`재작년에 심어서 올해 거뒀어` is the year before last). Not rivals either: a month, season or day without a year next to a time that sets a year, a decade, a recent or open-ended time, and a time in another sentence. (2) *A choice* (`A였나 B였나` · `A 아니면 B` · `A나 B`) is one vague span when the two touch or overlap, else `conflict`; `33살에서 36살 사이` and `20대~30대` keep both ends. (3) *A correction* (`4년 전 아니 6년 전에` · `4년 전이 아니라 6년 전에`) reads the later time, keeping the year of the earlier one when only a month, day or season is corrected. (4) *Not a time:* a count of machines (`차 30대를` — a noun counted with `대` right before the number, without a particle and without a time mark; any other `30대` is the age band, as in 5.2), a length of time before a word that only begins with `전` (`40년 전통`), words inside quotation marks or named with `(이)라는 · (이)란` + a noun (`모레라는 배` — but not a noun of time or speech, `2033년이라는 해` · `모레라는 소식`, and not an unquoted `모레라고`) — a text that is quoted as a whole is read without its marks. `전후` is vague like `쯤`. (5) *A time that describes a noun* (`4일 전에 산 배를 그저께 되팔았어` · `그저께 만난 동무랑 모레 또 만나` · `그저께 4일 전 이야기를 꺼냈어`) loses to the event's time, only for a closed list of describing verbs (`산 · 준 · 만난 · 빌린 · 타던 …`) with a noun chunk right before the other time, and not in reported speech; alone, it is the time of the sentence as before (`4년 전에 타던 배를 그려`). (6) *Ahead only:* `N년 안에 · 이내에` (months, weeks, days) is the point N years ahead, vague; looking back it is a length of time. (7) *A direction without a day* — `미래에 · 과거에` ask `unbounded` like `나중에 · 옛날에`, and `Ask.direction` carries the side the words hold. **`Span.phrase` is now only the text that matched** — 5.2 returned the whole sentence for relative and absolute days, months and years (`우리는 작년 여름에 연못을 팠어` gives `작년여름`). Public names otherwise the same, protocol stays at version 10 — a minor version.
  SDK 5.3 은 한 마디가 겹치지 않는 때를 둘 말하면 묻고, 때가 아닌 것은 읽지 않는다. `SpokenReading.Ask` 에 `candidates`(구간들 · 문장에 나온 차례)와 `direction` 을, `Ask.Reason` 에 `conflict` 를 더한다 — 새 칸이 없는 옛 JSON 은 그대로 읽히고 새 칸이 빈 `Ask` 는 5.2 와 같은 바이트를 쓴다. **부르는 쪽 예고 — 바뀌는 답:** ① 때가 둘 — 5.2 가 「절대 > 상대 > 생년」 차례로 하나를 고르던 자리에서, 한 마디에 나란한 때들(「그리고 · 쉼표」로 이었거나 앞 때 뒤에 쉼표가 서고 뒤 때에 「에」가 붙은 것)이 겹치지 않으면 `.ask` `conflict` + 후보다(「30년 전, 내가 30대에 우물을 팠어」 · 「재작년 그리고 올해 거뒀어」) · 그때 `day` 는 nil · 옛 차례는 겹칠 때의 이름 붙이기에만 남는다. 잇는 꼴(「-아서 · -고 · -고서 · -고 나서 · -다가 · -는데 · -지만 · 에 이어」)로 이었거나 사이에 풀이말이 낀 두 때는 5.2 의 답 그대로다(「재작년에 심어서 올해 거뒀어」 = 재작년). 그 밖에 다투지 않는 것: 해가 선 때 곁의 해 없는 달 · 날 · 계절 · 연대 · 최근 · 끝 없는 때 · 다른 문장의 때. ② 고름(「A였나 B였나 · A 아니면 B · A나 B」)은 맞닿거나 겹치면 합친 구간(흐림) · 아니면 `conflict` · 「33살에서 36살 사이」 · 「20대~30대」는 끝을 버리지 않는다. ③ 말 고침(「4년 전 아니 6년 전에」 · 「4년 전이 아니라 6년 전에」)은 나중 때 — 달 · 날 · 계절만 고치면 앞의 해를 잇는다. ④ 때가 아닌 것: 대로 세는 이름씨가 토씨 없이 맞닿은 셈(「차 30대를」 — 때 표지가 서면 나잇대 · 그 밖의 「30대」는 5.2 처럼 나잇대) · 「전」으로 시작하는 낱말 앞의 햇수(「40년 전통」) · 낫표 · 따옴표 안과 「(이)라는 · (이)란 + 이름씨」(「모레라는 배」 — 때 · 말을 일컫는 이름씨 앞 「2033년이라는 해 · 모레라는 소식」과 따옴표 없는 「모레라고」는 때 · 글 전체가 따옴표면 벗기고 읽는다) · 「전후」는 쯤과 같은 흐림. ⑤ 이름씨를 꾸미는 때(「4일 전에 산 배를 그저께 되팔았어」 · 「그저께 만난 동무랑 모레 또 만나」 · 「그저께 4일 전 이야기를 꺼냈어」)는 사건의 때에 진다 — 목록에 선 관형(「산 · 준 · 만난 · 빌린 · 타던 …」) + 이름씨 덩이 바로 뒤에 다른 때가 설 때만(그 밖과 옮긴 말은 5.2 의 답 그대로) · 홀로면 전처럼 문장의 때다(「4년 전에 타던 배를 그려」). ⑥ 앞일의 「N년 안에 · 이내에」(달 · 주 · 일)는 N년 뒤 · 흐림(지난 일이면 햇수). ⑦ 날 없는 방향 — 「미래에 · 과거에」는 「나중에 · 옛날에」와 같이 `unbounded` 로 묻고 `Ask.direction` 이 낱말이 품은 쪽을 싣는다. **`Span.phrase` 는 맞은 토막만이다** — 5.2 는 상대 · 절대 갈래에서 문장 전체를 냈다(「우리는 작년 여름에 연못을 팠어」 = 「작년여름」). 그 밖의 공개 이름 그대로 · 프로토콜 판 10 그대로 — 부 판이다.
- **Formats grow by adding fields**: readers keep unknown keys and write them back (`extra`), open vocabularies (`FormFactor`, `ScaleKind`, …) carry unknown words as they are. No form factor is required — Mac-only, iPad-only and TV-only projects are valid as a format. A project tool may still refuse a combination it cannot build, such as a TV-only project.
  형식은 칸 더하기로 자란다 — 모르는 키는 보존해 되쓰고, 열린 낱말은 모르는 낱말도 그대로 든다 · 어느 폼팩터도 필수가 아니다(맥 전용 · iPad 전용 · TV 전용도 형식으로는 선다 — 짓지 못하는 조합(TV 전용 같은)은 프로젝트 도구가 거절할 수 있다).
- **A major version freezes the contract**: the public surface a project uses keeps compiling across 5.x (source · file · wire compatibility — the gate diagnoses API breakage against the previous tag). Breaking changes only in the next major version; additions (new types · methods · fields with defaults that do not touch the wire) bump the minor — a new field in a message raises the protocol version, and raising a format version makes the reader refuse files the previous version wrote: both are major versions; fixes bump the patch.
  주 판은 계약 동결 — 프로젝트가 문 공개 표면을 5.x 가 계속 지킨다(소스 · 파일 · 와이어 호환 · 게이트가 직전 꼬리표와 깨짐을 맞댄다). 깨는 변경은 다음 주 판에서만 · 덧붙임(새 타입 · 새 메서드 · 와이어를 건드리지 않는 기본값 있는 새 칸)은 부 판 — 메시지 꼴에 칸을 더해 프로토콜 판이 오르거나 형식 판 상수가 오르면(읽개는 한 판만 읽어 앞 판이 쓴 파일을 거절한다) 주 판 · 고침은 수 판.
